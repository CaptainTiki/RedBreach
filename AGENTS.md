# Red Breach agent instructions

## Project
- Red Breach is a crunchy sci-fi shooter set at an industrial plant on Mars during an alien takeover.
- Workspace root: this folder. Godot project: `RedBreach/project.godot`.
- Keep shared instructions and documentation at the workspace root, outside the Godot project.
- Campaign arc: the colony is attacked, the aliens are discovered to have been present for a long time, and the goal becomes leaving Mars. The freight-access example is provisionally level 2 or 3 for an already competent player, targeting about ten minutes on a normal familiar run. See `docs/project-brief.md` and the mission walkthrough for quiet arrival rooms, persistent airlock/elevator transitions and destination-title presentation. These are design requirements, not authorization to skip the staged planning process.
- Preserve the existing nested project folder unless the user requests restructuring.

## Working on a different machine

- The repo is `https://github.com/CaptainTiki/RedBreach.git`, branch `main`. Work is developed on a desktop and a laptop, so **never assume a path outside the repo**. Everything inside the repo is relative; everything outside it is per-machine.
- **Godot** is the only external dependency the tooling needs, and the version must match (4.7). Set it once per machine:
  `setx REDBREACH_GODOT "C:\path\to\godot.windows.opt.tools.64.exe"`
  Every `tools/rebuild-*.ps1` reads `$env:REDBREACH_GODOT`, falls back to the desktop's Steam path, and throws a message naming the path it tried. `-GodotPath` still overrides both. Do not hardcode a new machine's path into the scripts.
- **Python 3** runs the drawing and generator scripts in `tools/`. They need only the standard library plus whatever the existing drawing scripts already import; they write into `docs/` and never touch a map unless they are named `bootstrap-*` or `apply-*`.
- Both addons under `RedBreach/addons/` are committed and must be preserved. After a fresh clone, run `godot --headless --path RedBreach --import` once so textures and `.map` files get their `.import` sidecars, then run the relevant `tools/rebuild-*.ps1 -Validate`.
- **Check the work actually arrived**: a rebuild on a new machine should reproduce the recorded counts exactly. Architecture lab: `ARCH_LAB_BUILD: 151 brushes; save=0` then `ARCH_LAB_QA: 1037 checks; 0 failures`. A different number means the map or the section module did not travel, not that the check is wrong.
- Uncommitted work does not travel. Before switching machines, commit and push; after switching, `git pull` before touching anything.

## Version every commit
- The starting project version is `0.0.001`, stored in `RedBreach/project.godot` as `application/config/version`.
- The first commit containing this setup establishes `0.0.001`. Each subsequent commit increments the final numeric component by one: `0.0.002`, `0.0.003`, etc.
- Use at least three digits for that component; after `0.0.999`, use `0.0.1000`.
- Include the version change in the same commit as the work. Increment once per commit, not once per file or editing session.
- Before committing, verify the staged scope and version against the previous committed project version.

- Two findings to preserve from that build. Registers separate by geometry and shadow, not tonal contrast - a charcoal plinth against pale infill turned the lower register into a black void. - Materials split by ELEMENT, not by height register: rib is one texture zone toe to beam, the bay is another and means the whole bay - wall at every height plus the ceiling between beams - and the floor stays continuous Dark/texture_06. Splitting by register instead made the wall read as three unrelated bands. - Lighting is built. The rib beams at 3.50 and the ceiling soffit at 3.75 already form a 0.25 m coffer in every bay, so recessed strips cost six brushes and no cutting. Two strips per bay near the coffer EDGES, not down the middle, so the wash rakes the wall and the chamfers read. EVERY bay carries a fitting; a per-bay tier in S.BAY_LIGHTS (lit / off) decides whether it is on, so turning a bay into a broken fitting is a one-word change with no geometry edit. An OFF fitting must NOT use an emissive material - a strip that glows while its bay stays dark reads as a mistake, because a fixture that is emitting should be lighting something. The scene's light nodes are generated from the same dictionary. Emissive material at `textures/greybox/Emissive/texture_01.tres`, picked up through `mapping/architecture_lab_map_settings.tres`, which is a lab-only settings resource so the freight maps are untouched.
- Brightness lives in the lights, not the emissive brush. Ambient is the strongest lever by far - 0.16 flattened the whole corridor straight back to the greybox look. Contrast between lit and off bays is managed with light RANGE (13 m against a 4 m bay pitch, so each fitting spills a bay and a half either side) rather than by raising ambient.

- Two brush-writing traps the jamb fill exposed, both of which silently break a solid.
