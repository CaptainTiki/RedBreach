# Red Breach agent instructions

## Project
- Red Breach is a crunchy sci-fi shooter set at an industrial plant on Mars during an alien takeover.
- Workspace root: this folder. Godot project: `RedBreach/project.godot`.
- Keep shared instructions and documentation at the workspace root, outside the Godot project.
- Campaign arc: the colony is attacked, the aliens are discovered to have been present for a long time, and the goal becomes leaving Mars. The freight-access example is provisionally level 2 or 3 for an already competent player, targeting about ten minutes on a normal familiar run. See `docs/project-brief.md` and `docs/freight-v2-walkthrough.md` for quiet arrival rooms, persistent airlock/elevator transitions and destination-title presentation. These are design requirements, not authorization to skip the staged planning process.
- Preserve the existing nested project folder unless the user requests restructuring.

## Working on a different machine
- The repo is `https://github.com/CaptainTiki/RedBreach.git`, branch `main`. Work is developed on a desktop and a laptop, so **never assume a path outside the repo**. Everything inside the repo is relative; everything outside it is per-machine.
- **Godot** is the only external dependency the tooling needs, and the version must match (4.7). Set it once per machine:
  `setx REDBREACH_GODOT "C:\path\to\godot.windows.opt.tools.64.exe"`
  Every `tools/rebuild-*.ps1` reads `$env:REDBREACH_GODOT`, falls back to the desktop's Steam path, and throws a message naming the path it tried. `-GodotPath` still overrides both. Do not hardcode a new machine's path into the scripts.
- **Blender** (5.x) builds the props: `setx REDBREACH_BLENDER "C:\path\to\blender.exe"` once per machine, like Godot; `tools/rebuild-props.ps1` falls back to the desktop's Steam Blender. Prop sources are `art/props/*.blend` at the workspace root (outside the Godot project, which would try to import them).
- **Python 3** runs the drawing and generator scripts in `tools/`. They need only the standard library plus whatever the existing drawing scripts already import; they write into `docs/` and never touch a map unless they are named `bootstrap-*`.
- Both addons under `RedBreach/addons/` are committed and must be preserved. After a fresh clone, run `godot --headless --path RedBreach --import` once so textures and `.map` files get their `.import` sidecars, then run the relevant `tools/rebuild-*.ps1 -Validate`.
- **Check the work actually arrived**: a rebuild on a new machine should reproduce the recorded counts exactly. Freight v2: `ZFIGHT: ... 0 VISIBLE`, `FREIGHT_V2_BUILD: 1606 brushes; 181 lights; 7 ladders; 30 kit pieces; 664 navigation polygons; save=0` and `MARKER_QA: 830 checks; 0 failures`. A different number means the map or the section module did not travel, not that the check is wrong.
- Uncommitted work does not travel. Before switching machines, commit and push; after switching, `git pull` before touching anything.

## Version every commit
- The starting project version is `0.0.001`, stored in `RedBreach/project.godot` as `application/config/version`.
- The first commit containing this setup establishes `0.0.001`. Each subsequent commit increments the final numeric component by one: `0.0.002`, `0.0.003`, etc.
- Use at least three digits for that component; after `0.0.999`, use `0.0.1000`.
- Include the version change in the same commit as the work. Increment once per commit, not once per file or editing session.
- Before committing, verify the staged scope and version against the previous committed project version.

## Plan levels before building
- Plan each level on paper first as a top-down 2D spatial layout before constructing it in TrenchBroom or Godot.
- Record rooms and zones, routes and connections, story beats, objectives, encounters, items, keys, and locked gates.
- Preserve the plan or its transcription in `docs/` and resolve spatial intent with the user before 3D blockout.
- Rooms can themselves be height transitions: consider mezzanines, upper/lower entrances and internal stairs during room layout. Main-floor labels do not require single-level rooms. Use this selectively, draw each doorway elevation and preserve key/gate reachability; update the elevation plan when moving a reserved corridor stair into a room.
- Begin with a small TrenchBroom pipeline test, then validate traversal and scale before expanding.
- For missions, follow the user's staged workflow: agree on the step-by-step walkthrough in words, review a top-down 2D plan with key/gate reachability, build and walk an empty blockout, make an enemy/pickup pass, then build and playtest. Check empty traversal and progression before the populated run. The current mission is freight v2 (see Clean-slate direction below).

- Read `docs/spitter.md` before refining the ranged enemy. User intent: fast spit that is only just dodgeable, encouraging quick kills. Starting speed is 35 m/s; aim tracks until release, then flight is fixed.
- `combat/gym_spitter.tscn` has a half-second jaw-opening charge and a bright yellow-green throat. The open front mouth takes 3x damage; 150 health means two accurate pistol mouth hits or six body hits. Nonlethal weak hits do not cancel the attack.

## Standing design rules (user)
- The first freight mission (the F5/F6 blockout, layouts 01-12, Route A, Registration and Screening) was replaced by freight v2 and removed in the 2026-09-26 cleanup; it is in git history before that commit. The rules it produced are in `docs/architecture-language.md`. Read it before any room pass. In short:
- Separate adjacent or perpendicular door openings with real wall returns (about 1 m of solid wall beyond a frame) or a designed lobby.
- Room proportions: length at most 2x the clear width, 3x for a deliberately elongated room, for every subdivided room too. A longer strip is a corridor.
- Height follows function: lower ceilings (about 3.5 m) in offices and staff spaces; a tall room needs equipment, an occupied upper floor or a deliberate focal point.
- Stairs go along room sides by default, with level landings and a player-eye view of the receiving floor before the descent.
- Every texture change needs supporting geometry (a rise, drop, border brush, trim or physical seam). One material on an uninterrupted flat floor; never a painted walkway instead of a real level change.
- Every room owns its walls: at least 0.25 m per side, 0.5 m between two spaces; two rooms never share one wall brush.
- Compose complete assemblies (a focal piece, its working space and supporting architecture) and plan footprints with movement and retreat space. Block in ribs, frames, angled upper corners, service trunks and light housings early.
- Reserve bug-entry hatches while composing rooms: aperture, sealed backing, emergence volume, landing and an enemy-sized exit. Never on the only retreat path or a stair or door landing.

Emissive machines get a little bloom, not a reactor about to go critical; keep equipment bodies dark around emissive parts. **Fog is dark and neutral inside and warm dust only outside**: a neutral global volumetric fog, a box FogVolume over the exterior, and warm distance fog beyond 60 m.

- **Texture rules (user, 2026-09-25).** Never use a non-tiling texture where a surface repeats. `tools/audit-textures.py` writes `docs/texture-catalog.json` (per axis: T seamless, P panel, X never repeat; manual `FEATURES`/`PANELS` overrides). `style_lab.ROLE_TILING` declares HV / H / fit per role, and `write-style-lab-scene.py` refuses a mismatch; rerun the audit after adding textures. Busy textures (the dotted grate) are **features**: one or two squares with an elevation change, never a whole floor. Seams sit on geometry: brushkit `uv_origin` starts panels at corners, segment edges and rib stations; `uv_u` makes floors and ceilings follow a run; `fit` roles are fitted whole to their face. This supersedes the world-origin UV rule for style and kit maps; the Kenney gym maps keep theirs. Look entries may carry an albedo tint `(texture, (r, g, b))`.
- **Junction rule (user, 2026-09-26):** a corridor meets a room through its own profile. The room wall is cut to fit, and the corridor's rib stands at the room face with a low sill for any floor-texture change. There is no bulkhead slab at rooms (`kit_lab.JUNCTIONS`: open / door / door_low). Bulkheads remain only for profile-to-profile changes inside a corridor. **Texture packs:** textures will be organised as packs by area function (admin, machinery, residential) once the story defines the areas; a pack is a named role-to-texture set like today's `LOOKS`.
- **Texture choices (user, 2026-09-26):** ceilings continue their look's slope and wall material; QUOD's corrugated tex90 is for container sides and roll doors only. A door is cut into the plain `door_panel` role. A room shares one texture origin (its corner) across all walls, junction pieces and door panels, so patterns run straight across cuts.
- **Vertical interest (user, 2026-09-26)** includes 1–2 steps, stairs and ladders into wells with secrets, accumulating as a running elevation story along the route (for example: 2 steps down, round a machine, 2 more down, a 4-step drop in the corridor, a 10-rung ladder up to +6). Record every room's entry and exit elevation and a running tally in the walkthrough.
- **Room recipe (user, 2026-09-26):** purpose → walk path (with a retreat line) → blockers (equipment with real footprints) → vertical interest → secrets → walls LAST, wrapping path and blockers, never a rectangle drawn first → look and light. Build 4–5 room studies standalone before composing and connecting the level. Rooms are not hallways with a tumor.

## Props (user, 2026-09-27)
- **Props are placed in GODOT, not TrenchBroom, after a level's architecture is solid** (a TrenchBroom point entity shows no facing or footprint). TrenchBroom keeps the architecture, the big machines that shape a room and the progression kit.
- **A light is a prop:** a Godot scene with an imported fitting and its light as a child, tuned in the inspector on the prop's root (`PropLight`: lit, color, energy, light_range, shadows, `wire`, flicker, spin_speed). A dead fitting never glows (off darkens the lens). Hanging fittings' wires run up through the ceiling into the void; flush fittings sit against it. Types: fluorescent, halogen, wall sconce, desk lamp, floor uplight, emergency beacon (ceiling and wall bracket).
- `tools/props.py` is the single source of truth (parts named by look/role, like map faces, at the level's texel density). `tools/rebuild-props.ps1 -Validate -Capture`: Blender builds `art/props/<name>.blend` and exports `RedBreach/props/<category>/<name>.glb`; `tools/write-props.py` maps each material to the level's own through the .glb import settings and writes the prop scenes, the gallery and `props_data.json`; `validate_props.gd` (153 checks) and `capture_props.gd` (`docs/props-gallery.png`). **F12** opens the gallery. List a prop in `props.HAND` to hand-edit its .blend without it being regenerated. Read `docs/props.md`.
- Freight's props go in `missions/freight_v2/freight_v2_props.tscn` (instanced as `Props`; created once by the scene writer and never rewritten). As light props take over a room, retire its `rb_light` entities from the generator. Furniture collision is not yet in the navigation bake.
- A `.tscn` Transform3D writes its basis ROW by row; writing axes inverts every rotation.

## Corridor findings (architecture labs, removed)
- The architecture labs (F7 straight run, F8 corners and T) were removed in the 2026-09-26 cleanup; the kit lab carries the corridor profiles. `docs/corridor-lab-findings.md` keeps what they found. The load-bearing rules:
- One global 4 m rib beat along the centreline, never restarted after a turn; a station inside a turn is skipped, not nudged.
- 52 m is the MAXIMUM straight run. Interrupt before it with corners, T junctions, doors, debris to walk around or low cables to crouch under.
- A single turn uses the 45 degree leg; a T or 4-way stays square, with ribs set back 6 m from the junction centre.
- Lit by default, off by deliberation: every bay has a fitting, and an off fitting is dark, never emissive. Ambient is the wrong lever; put the light node below the soffit; a fitting only needs a ceiling, a rib needs two walls.
- Brush traps: define each face plane by three truly distinct points; never share a vertex between a tapering prism's two rings; compare the generator's brush count with the build's collision count.
